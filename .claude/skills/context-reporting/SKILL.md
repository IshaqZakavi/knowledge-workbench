# Context Reporting

Selected adaptation of the knowledge-work method for this public template.

Start with the question, audience, time horizon and permitted workspace. Use search to find candidates, then read authoritative records and their latest updates.

For a status question, inspect the goal, active work, observed process run and output separately. Follow `origin` and `supporting` to evidence. Use `related` for context, not automatic corroboration. Include dates so an older decision is not mistaken for a current state.

For meeting preparation, authored person context can help surface open commitments and prior requests. Keep provisional working hypotheses separate from observed behavior. Do not infer intentions or personality from an uncertain transcript or tone.

Answer the actual question with sources, unresolved issues and the decision or next step that needs attention. Do not invent a completion percentage, benefit metric or confidence score. Verify factual and sharing boundaries before preparing an external version.

In the fictional pilot, the appropriate status is: scope agreed, terminology list complete, source comparison still in progress, approval owner unresolved, brief still draft. The read-only tools can expose that evidence; no generative report engine or automatic approval is included.
