# Review And Route

Selected adaptation of the knowledge-work method for this public template.

Read the source, its curated record and related goal before routing proposed work.

Separate these objects: a goal is a desired outcome, a backlog item is a durable work thread, a candidate is proposed work, a task is accepted work, a run is an execution attempt and an output is an artifact. Source evidence is none of those by itself.

Check whether the work already exists. Identify the appropriate goal and project boundary. Preserve unknown ownership and due dates; do not fill them in for completeness. Ask for missing acceptance or external-action authorization when required.

Only after authorized review should a candidate become accepted work. A rejected candidate does not invalidate the source observation. Do not create external tickets, send messages, merge, deploy or publish merely because a note suggests doing so.

For execution in the broader design, preserve inputs, checkpoints, decisions, produced artifacts and verification. The public sample illustrates records; it has no task executor, candidate database or resumable runtime.
